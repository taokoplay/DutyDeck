# LibTV 媒体

LibTV 的官方接入来自 https://github.com/liblib-ai/marketplace，远程 MCP 为 `https://mcp.liblib.tv/mcp`。DutyDeck 复用 Pi MCP 工具桥与系统加密的 OAuth 凭据，不需要 Codex 插件运行时，也没有仓库内可执行的本地 CLI。

## 连接与能力发现

- 仅在用户明确选择 LibTV 时使用。当前回合必须实际提供 `mcp__libtv__` 工具；没有时，引导到「设置 → 媒体 → LibTV」选择当前工作区并完成授权、连接检查，再在下一轮选择 `#libtv`。不要自行安装命令行、复制其他客户端 token 或读取浏览器 Cookie。
- 连接后先阅读服务端工具说明与实际工具 schema，再调用服务端当前提供的 `get_capabilities` 或等价的能力发现工具。按返回的模型、输入限制与参数执行，禁止猜测工具名、模型 ID、任务字段、CDN 或下载 URL。
- 官方工具可能操作账户、项目、媒体、任务和导出；只调用当前需求需要的能力。参考素材只能使用用户已授权的资产和服务端真实媒体 ID，不能把本机任意目录自动上传。

## 执行、等待与交付

1. 读取当前 LibTV 项目与版本，明确用户目标、选定模型、数量和可能消耗的 LibTV 积分。执行前遵守当前 Agent 工具权限与用户授权；DutyDeck 的统一媒体自动执行开关不代表已批准所有远程 MCP 操作。
2. 按实际工具 schema 准备、提交一次生成，保存返回的项目、节点、任务或会话 ID。每次等待和恢复都查询同一个任务，不能按显示名称寻找“最近一次”任务。
3. 请求超时、断线或取消本地等待不能证明远端失败。先按已保存 ID 读取状态，不重复提交可能收费的任务；只有服务端明确支持取消且返回成功，才可报告远端已取消。若没有可查询 ID，报告结果未知并请用户检查 LibTV 项目。
4. 任务明确成功后读取真实输出，交付工具返回的媒体或可访问链接，并说明其在 LibTV 中的归属。不能声称已经入库 DutyDeck，也不能伪造 `assetRef`、`runId`、checksum 或模型引用。
5. 影像作品与画布流程不得绕过已有任务绑定、审查与采用门禁。LibTV 远端结果未经宿主授权导入并取得真实受管资产引用，不能冒充作品候选、画布资产或自动完成验收。

账号未授权、权限不足、配额不足、任务失败和结果未知需分别说明；不要在回复或普通文件里回显 token、授权码或原始认证错误载荷。
