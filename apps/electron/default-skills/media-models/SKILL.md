# 统一媒体模型

当用户要生成或编辑图片、视频、动图、旁白、语音、播客片段、歌曲、音乐或音效，或询问当前配置了哪些媒体模型时，使用本 Skill。它负责一次媒体任务的模型发现、能力匹配和生成交付。

## 触发边界

- 用户明确要求图片、图片编辑、视频、首帧/参考图生视频、语音、旁白、声音复刻、歌曲、音乐或音效。
- 用户询问“有哪些图片/视频/音频模型”“哪个模型能写歌/配音”，或指定供应商、模型、速度、成本、画幅、音色、格式等条件。
- 用户要一次独立媒体产物时使用本 Skill。直接理解自然语言，不要求先输入 `/media-models`、`/模型名` 或选择专业模块；斜杠菜单只是精确选择的快捷入口。
- 只要求提示词、文案、模型比较或代码修改时，不发起生成；查询当前模型仅做发现和说明。
- 用户要画布节点或画布工作流时，仅在本轮已选择画布模块、提供了 `canvas_*` 工具时读取并转交 `canvas-production`；未选择时提示选择，不自动启用。
- 已选择影像模块的多镜头、连续迭代、候选或验收任务沿用 `visual_production_*` 作品流程；不因任务复杂而转入未选择的画布。
- 用户明确要求修改项目代码时，执行普通代码任务，不用媒体 Skill 替代实现。

## 第一步：发现所有真实模型

用户明确指定 LibTV / Liblib 时先读取 `libtv-media`。LibTV 使用官方远程 MCP，不在统一模型目录；不能因 `media_list_models` 没有 LibTV 就声称它不支持生成，也不能构造虚假的 `media:...:libtv:...` 引用。不得绕过影像作品或画布任务的绑定、审查与采用门禁；没有受管资产时只能交付 LibTV 远端结果，不能宣称已成为作品候选或画布资产。

用户明确指定 ComfyUI 时先区分工作流路由：它不是统一模型目录中的单个模型，列表没有它不能据此判断未配置，不要伪造 `media:...:comfyui:...` 引用。普通会话无需选择画布或影像模块；本轮提供 `media_discover_workflows` 等工具时读取 `comfyui-workflows`，按需求发现服务器工作流、模型与节点，必要时编写并校验，再按独立工作流链生成。统一目录未找到用户指定模型时，不能据此断言整个项目没有它；工作流工具可用时继续查询 ComfyUI 的真实工作流与资源，身份仍不明确才向用户核对，不把相似名称当作同一模型。缺少工具时如实说明本轮能力边界，按 `MEDIA_PROJECT_REQUIRED` / `MEDIA_SERVICE_UNAVAILABLE` 处理，不把选择专业模块当作独立任务的前提；不访问内部配置或用脚本绕过，也不擅自替换用户指定模型。

对统一目录路线，每次新的媒体任务都先调用 `media_list_models`，并按 `nextOffset` 分页直到返回 `nextOffset: null`。这个工具返回统一图片、音频和视频目录中的稳定 `ref`、`kind`、`capabilities`、`available`、`adapterId` 、`parameters` 参数约束和不可用原因。

普通对话直接使用统一目录；仅当本轮提供 `media_list_api_models` 且需要维护历史 API 配置时才查询该兼容入口，同样分页读完。它可能返回已经配置但仍是 `configuration-only` 的条目；这类条目只能用来说明配置缺口，不能执行。两个结果按稳定引用、供应商、配置 ID 和模型 ID 去重，不能因为显示名称相同就合并不同模型。

统一生成链只把同时满足以下条件的条目作为执行候选：

- 统一目录：`available === true` 且存在 `adapterId`。
- API 目录：只有返回了该执行工具明确接受的稳定引用、`available === true` 且 `support.state === "supported"` 时才可执行；没有统一 `ref` 的 API 条目不能把 `profileId` 冒充 `modelRef`。
- 模型能力与用户意图匹配，不能把同一 `audio` 条目自动当成语音。

分页、过滤或去重失败时，保留错误并说明，不能把部分目录当成完整目录，也不能静默退回文本回答。

## 能力匹配

按返回的真实 `capabilities` 选择：

| 用户意图 | 必须匹配的能力 | 说明 |
| --- | --- | --- |
| 生成图片 | `text-to-image` | 文生图；有参考图时改用 `image-to-image` |
| 编辑图片 | `image-to-image` | 只使用已授权的媒体资产引用 |
| 生成视频 | `text-to-video` | 用户给首帧或参考图时使用 `image-to-video` |
| 生成语音、旁白、播客片段 | `text-to-speech` | 需要声音样本时必须有 `voice-cloning` |
| 声音复刻 | `voice-cloning` | 需要已授权的音频资产，不能把本地路径直接传给工具 |
| 写歌、生成音乐或音效 | `text-to-music` | 只有真实返回该能力且可执行的模型才可使用 |

`text-to-music` 目前可能只出现在配置目录的 `configuration-only` 条目中。遇到这种情况要明确告诉用户：模型已配置，但 DutyDeck 当前没有对应执行 adapter；不要把 TTS 模型、LLM 或旧图片模型冒充音乐模型。若没有任何可用候选，说明缺少的能力、已有但不可用的模型及原因，并引导用户到媒体设置补齐配置。

## 选择规则

1. 用户明确指定 `modelRef/ref`、供应商或模型名时，优先精确匹配当前目录；找不到时按上述工作流路由补查，仍无证据则说明已查范围与未确认项，不猜测相似名称。自然语言中指定的供应商或模型名，与 `/模型名` 选择具有相同的选型意图，但仍须查询目录取得真实 `ref`；指定供应商或同名模型仍有多个候选时，简短确认具体模型，不自行取第一项。
2. 用户未指定模型时，优先使用当前模块已保存的绑定，再使用设置中实际存在的对应类别默认模型，否则只在唯一满足能力要求的可执行候选时自动选择。仅当当前工具或宿主上下文明确提供默认配置时才使用，不能把目录首项、上次生成记录或供应商参数默认值当成默认模型。仍有多个候选时请用户选择，不能按目录顺序取第一项；只展示符合本次能力要求的候选，不要求用户改用斜杠命令。
3. `available: false`、`configuration-only`、缺凭据、停用或未接 adapter 的条目不可执行；它们只能作为诊断信息展示。
4. 不使用 `proma-generate-image`、`proma-gpt-image-2`、固定 GPT/Gemini/Nano Banana 名称或旧 Proma Cloud 凭据。模型名称必须来自本次目录读取。
5. 用户要求低成本或快速生成时仍先看真实能力和设置，不因 Skill 被触发就自动购买、切换供应商或扩大生成数量。

## 统一执行链

对带统一 `ref` 的可执行模型严格使用以下顺序：

```text
media_list_models
→ media_prepare_generation
→ media_execute_generation
→ media_wait_generation 或 media_get_generation
→ media_list_assets
```

取消当前任务时使用 `media_cancel_generation`，并传入明确的 `cancelIntent: "explicit"`。准备成功只表示参数和配置通过，不表示供应商已经收到请求；必须等待并报告真实终态、`runId`、模型引用、能力和输出资产。

普通对话无需先选择专业模块；收到 `MEDIA_PROJECT_REQUIRED` 时先提示为当前对话选择项目，收到 `MEDIA_SERVICE_UNAVAILABLE` 时说明服务尚未就绪。不要读取渠道配置、解密凭据或通过脚本绕过宿主；入口不可用不能推断密钥无效。

执行前遵守当前媒体自主策略和付费审批：`ask` 逐次确认，`automatic` 只在用户既定任务与预算内执行。计划模式只发现、分析和准备，不执行生成或导入素材；Skill 被加载不改变当前工具权限。等待超时只代表当前状态未知或仍在运行，继续使用原 `runId` 查询，不重复提交同一付费任务。失败、取消、运行中、`unknown` 和成功必须分开报告；`unknown` 只查询原任务，不自动新建任务。取消只保证停止本地处理，不能声称供应商已经取消。

## 输入和资产安全

- 参考图片、音频和视频只使用 `media_list_assets` 或 Host 提供的已授权资产引用。
- 不把任意本地路径、凭据、远端 URL、供应商文件名或旧 Skill 示例直接塞进统一媒体工具。
- 需要引用已有媒体时，先获取可信 `assetRef`，再按模型能力传入；类型不匹配时先说明缺口。
- 语音任务报告模型支持的音色、格式和长度限制；歌曲任务报告模型真实支持的音乐类型和限制。
- 生成成功后交付受管媒体资产或明确资产引用，不能凭文件名猜测输出媒体类型。

## 与 canvas-production 的交接

只有本轮已选择画布模块且用户需要画布交付时，才转交 `canvas-production`，由它负责画布上下文、节点关系、版本、审查和采用合同。影像作品的多产物与持续迭代沿用已选择的影像模块。本 Skill 负责媒体模型目录的能力发现及单次生成，不自动启用其它专业模块。
