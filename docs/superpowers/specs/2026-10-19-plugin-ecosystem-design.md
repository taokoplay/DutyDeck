# DutyDeck 插件生态、资源与分发规范草案

日期：2026-10-19。状态：供评审与协作拆分的设计草案，尚未实施；当前不构成已发布 SDK 或包格式承诺。

用户已明确要求：由 DutyDeck 制定统一插件规范和开发脚手架，开发者在其中实现可执行业务模块并打包交付；项目/工作区已有的 Skills 继续由现有 Skill 系统管理，插件只声明稳定 Skill 引用，不复制或拥有 Skill 正文；提示词、工具、服务、界面、状态与产物遵循统一合同；支持安装、卸载与关闭、独立安装包、团队私有分发和设置中的插件市场。

2026-10-20 边界修正：Skill 不是插件交付物。插件的最小价值是“模块运行时 + Agent 工具 + 右侧 Surface + 受控服务 + 状态/生命周期”；Skill 只作为项目或工作区的既有知识资源，由插件通过稳定 ID、版本范围和作用域引用。当前 `content` 包仅作为旧版兼容形态保留，新的标准脚手架以 `module-runtime`/受信 runtime 为目标；当前宿主尚未开放任意第三方可执行 runtime。

2026-10-19 语义修正：用户说的“风格”指统一插件方案及开发规范。本文以一个标准脚手架、一套包格式为主线；设计类业务需要的视觉约束只是插件内部的可选资源，随所属插件管理，不构成额外的安装分类或首版前置能力。

首版范围和优先顺序以 [插件模块首版规划](../plans/2026-10-19-plugin-module-v1-plan.md) 为准：先完成模块 runtime 脚手架、Skill 引用解析、插件中心、私有源和独立作者工具，不等待六个内置业务模块全部迁出。

本规范覆盖旧计划 `../plans/2026-10-18-agent-module-pluginization.md` 中“会话长期启用/固定”“目录只留在 Skills 页”等过时产品方向，保留已有实现与验证记录。当前消息显式选择专业模块、浏览器/终端自动按需调用的约定继续有效。

## 1. 结论与现状差距

推荐把插件作为**可独立交付的业务模块**，模块是包中面向用户的入口，工具、受控服务、右侧 Surface、状态、生命周期和产物类型是该入口的贡献；Skill 由项目/工作区现有系统提供，插件只声明引用。一个插件可以包含多个模块，但首批官方插件尽量一个业务模块一个包，避免一次关闭影响无关能力。

我们负责清单与目录、模块命名、Skill 引用解析、提示结构、SDK 接口、界面约定、生命周期、校验和分发标准；开发者负责业务逻辑、工具/服务/Surface 和测试。插件安装后，其专业模块由用户在消息中选中，宿主才解析该模块声明的 Skill 引用并开放已受支持、已授权的能力。

当前已经有清单、注册表、消息选择、Skill/prompt 接入、工具门禁、审计、清单安装管理和内置 Host 框架。仍缺少真实包资源所有权、全局开关、版本事务、动态工具/界面贡献、发布者身份、市场源、开发 SDK。

## 2. 方案选择与交付边界

| 方案 | 收益 | 代价 | 选择 |
| --- | --- | --- | --- |
| 继续扩充清单 | 变更最少 | 不能随包安装 Skills，不能独立交付业务 | 不作为最终目标 |
| 统一脚手架直接面向模块 runtime，先做官方受信模块 | 与用户目标一致，工具/面板/服务有统一生命周期 | 需要 broker、权限、签名和隔离先行 | **推荐** |
| 首版开放任意第三方代码和原生依赖 | 扩展范围最大 | 沙箱、升级与跨平台运维负担过大，拖延基础体验 | 不作为首版 |

统一脚手架和包格式通过 `profile` 声明执行能力级别。下列取值仅用于兼容与准入校验，不是市场业务分类：

- `content`：旧版兼容形态，只能声明已有 Skill 引用、纯文本提示、静态元数据和声明式设置；不得携带或复制 Skill 正文，也不注册任意 Node/系统工具。
- `module-runtime`：标准目标形态，提供业务工具、受控服务、右侧 Surface、状态和生命周期；当前只允许宿主内置或经 allowlist 的官方 provider。
- `trusted-runtime`：`module-runtime` 的受信执行实现，先用于官方模块迁出；签名正确或来自私有源不自动获得该资格。

非可信可执行插件的开放是单独发布门槛：真实文件/网络/凭据/资源隔离验证通过前拒绝安装该能力配置，不能以独立 utility 进程或 JS VM 冒充安全沙箱。这不阻止第三方先开发内容包或在隔离的开发数据根贡献业务插件源码。

## 3. 术语、身份与可见命名

### 3.1 对象边界

| 对象 | 职责 | 示例 |
| --- | --- | --- |
| 发布者 | 包身份与发布密钥的所有者 | `acme`，显示“Acme 团队” |
| 插件 | 安装、升级、关闭、卸载的单位 | `acme.design-kit`，显示“设计助手” |
| 模块 | 用户在消息中选择的能力入口 | `acme.design-kit.design`，显示“页面设计” |
| Skill 引用 | 项目/工作区既有的操作知识与工作流 | `project:skills/page-design` |
| 提示 | 有角色和用途的有界文本资源 | `acme.design-kit/prompts/workflow` |
| 设计约束资源 | 插件内部可选的视觉约束、说明与示例 | `acme.design-kit/styles/clean-business` |
| 工具/界面 | 通过 Host 合同注册的执行或展示能力 | `acme.design-kit/tools/inspect` |
| 插件源 | 提供索引、下载与更新的分发渠道 | 官方、社区、团队私有 |

稳定 ID 使用英文小写命名空间，与中文显示名分离；名称修改不影响历史引用。包版本、资源版本、清单格式版本、Host API 版本和产物数据版本是五个独立维度，不能混用。

新插件 `id` 使用 `<publisherId>.<pluginSlug>`，模块 ID 使用 `<pluginId>.<localModuleId>`。插件运行资源 ID 使用 `<pluginId>/<kind>/<localId>`；Skill 不产生插件资源 ID，插件通过 `{id, scope, versionRange, required}` 稳定引用项目/工作区 Skill。共享能力明确声明导出及消费者，不靠同名匹配共享。

内置模块现有 ID（例如 `interaction-design`）和 `builtin.*` 插件身份保留宿主专属兼容映射，不批量重写历史会话。第三方不得占用这些名字；迁出后的官方包只有通过宿主的发布者/密钥迁移授权才能继承原身份。短别名仅在唯一时可解析；存在歧义必须展示候选并拒绝静默选择第一个。

首版的内置模块以宿主提供的虚拟包记录参与依赖解析，标记 `managedBy: host`，包含独立的能力版本与 providerDigest；不能从市场下载、覆盖或卸载。界面显示“内置 · 随应用更新”。即使业务尚未迁出，关闭仍覆盖 Agent、独立工作台、深链和旧命令的新业务准入；历史作品可只读访问，共享基础服务按自身消费者继续管理。

### 3.2 Skills 展示规则

- 主标题采用“交互设计 · 页面设计”“影像创作 · 镜头规划”；所属模块是独立标签，来源另外显示“官方 / Acme 团队 / 本地开发”。同名模块再显示插件名区分。
- 详情显示插件、模块、作者、版本、是否已自定义、使用范围、必需/可选和可用状态；高级详情显示稳定 ID 和内容摘要。
- Skill 的真实来源、作用域、版本和 hash 由项目/工作区 Skill 注册表提供，不能信任插件 manifest 自报归属。
- 独立用户 Skill 继续显示“个人 / 项目”，不强制归入插件；用户创建的同名 Skill 不会被插件覆盖。
- 插件安装只保存 Skill 引用和解析锁，不复制正文到插件目录；运行快照记录实际解析到的 Skill revision/hash。
- 必需 Skill 缺失、版本不兼容或项目未授权时模块不可运行，说明阻断项；可选 Skill 失效时显示降级能力。
- 点击专业 Skill 只插入一个受控草稿操作：清楚显示“将同时选中交互设计”，用户点击该动作后同时加入模块 chip 和 Skill chip；手写引用而未选择模块时直接阻断，不在后台隐式选模块。

## 4. 启用、选择、运行与关闭

### 4.1 四种事实分别存储

| 状态 | 用户操作位置 | 语义 |
| --- | --- | --- |
| 已安装 | 设置 → 插件 | 包已校验并存入本地 |
| 已启用 | 设置 → 插件 → 已安装 | 当前数据根允许使用；不等于给任何会话注入能力 |
| 本条消息选中 | 输入栏模块菜单/chip | 本轮允许接入所选专业模块 |
| 运行健康 | 插件详情/调用记录 | 已实际启动服务、执行结果或故障；不由安装状态推断 |

一期全局开关作用于共享数据根；不同项目可记录限制和风格偏好，不能绕过全局关闭。暂不新增另一套项目级“自动启用专业模块”功能。

安装确认页提供可见的“安装后启用”选项，默认选中；兼容/授权条件不满足则显示“已安装，待配置”，不可标成可用。只有 runtime 才可能需要按需启动服务；安装或启用不会启动昂贵模型、网络任务或后台业务轮询。

专业模块准入必须同时满足：包可信且可用、插件已启用、依赖兼容、当前消息显式选择、必需资源有效、作用域授权允许。工具执行还须通过原有业务权限和审批，选择模块不等于放宽权限。

浏览器、终端以及宿主固定基础能力继续按需自动调用，不进入专业模块选择菜单。第三方包不能通过声明 `automatic` 冒充基础能力。

### 4.2 停用状态机

`enabled → disabling → disabled`。

1. 请求关闭时先关闭新任务准入：消息、手写 Skill、模块命令、排队、Automation/Collaboration 以及内部委派的所有入口都检查同一开关。
2. 运行中的任务默认按已取得的版本租约排空；UI 显示“停用中，等待 N 个任务结束”。此时尚未“已停用”，用户仍能选择“停止任务并停用”。
3. 新消息若含失效 chip，保留文字并标出原因，发送前阻断；不能悄悄删除模块后将正文交给普通 Agent。
4. 尚未派发的队列项转为可见阻断状态，保留原身份和原因，不自动改为其它模块或自动重放；重新启用后由用户明确重试。Automation 的下一次触发报告一次可行动失败，不反复弹窗。
5. 立即停止沿既有取消链等待确认，不假设远端任务/付费请求已经回滚；终态不明时显示“结果待核实”。有取消确认的运行先释放工具和资源，再变为 disabled。
6. 关闭收束后移除可执行工具和激活入口、释放资源；历史记录保留。再次启用不恢复旧任务，也不自动选中该模块。
7. 设置中的“已启用”与健康中的“启动失败”可以同时存在；失败必须可诊断、可重试，不能自动无限重启。

停用必需依赖时先展示影响范围：所有传递消费者立即停止新准入，保留其 enabled 偏好但标记 `blocked-dependency`；持有该依赖的消费者运行一并纳入排空。再次启用依赖只恢复可用性，不重放任务。仅链接名称的元数据引用不构成执行依赖；所属插件停用或选定资源失效时，保留草稿选择并报明原因，不静默替换资源。

关闭后的历史产物通过宿主通用只读查看器、导出或“重新启用插件”入口访问，不能为展示旧作品偷偷启动已禁用插件。

## 5. 统一开发规范与包内资源合同

### 5.0 平台规范与业务资源的边界

- 所有插件遵循同一套目录、身份、版本、模块入口、资源引用、权限、生命周期和测试规范；脚手架与校验器共同落实，不能仅靠开发者阅读说明。
- Skills 使用统一章节与模块归属；提示词声明用途、输入变量、输出约束、优先级及预算。模板中的占位变量必须显式声明并由宿主受限替换，不能执行表达式。
- 宿主拥有的设置和管理界面统一使用现有 Radix/shadcn primitives 与主题变量；后续自定义插件界面通过公开 UI 合同遵守布局、主题、键盘和状态反馈约定，不导入宿主内部组件。
- 插件生成的业务产物遵循自身领域规范。设计类插件可包含视觉约束，运维、接口等插件不需要生成无关的设计资源。
- 插件的界面开发规范与它指导模型生成页面的视觉要求分别表达；后者不能覆盖宿主管理界面的统一体验。

### 5.1 Skill 引用与提示的职责

- Skill 继续由项目/工作区现有 Skill 系统维护，保持 `name`、`description`、`version` 和既有正文合同；插件清单只声明 `skillRefs`，不得携带 `SKILL.md` 或覆盖正文。宿主按作用域、稳定 ID、版本范围和项目授权解析引用。
- Skill 引用必须显式声明 `id`、`scope`、`versionRange` 和 `required`；解析结果写入运行快照，禁止每轮按名称重新择优。
- 必需规则须可验证，不能把“已调用工具”等同“已完成目标”。不得要求关闭审批、读取别的插件私有目录或覆盖宿主/项目规则。
- 提示声明 `kind`：`workflow`、`output-contract` 或 `style-guidance`。宿主安全规则和真实工具 schema 不能由插件 prompt 覆盖。
- 提示资源是数据而非文件访问授权，不允许任意绝对路径、远程脚本、环境变量展开或执行模板表达式。
- 插件运行资源默认私有。跨插件共享只通过显式 `exports` 和精确依赖绑定；公开的基础资源不得夹带另一个专业模块的工作流或工具。业务 Skill 引用必须要求其所属模块的本轮选择，不能通过 A 引用 B 绕过 B。

共享资源另有 `shared-knowledge` 类型，记录包所有者和消费者，不作为无归属的业务 Skill。其内容只允许数据/模型说明等被动知识，不贡献工具或任务工作流；已选消费者通过宿主核验的导出接口加载，供应包必须启用且持有资源租约。既有 `media-models` 迁为宿主拥有的共享资源适配，不以“画布 Skill”身份授权影像模块。业务 Skill 的 `requiredModuleIds` 由可信所属关系推导；作者不能通过自报 shared 类型抹去已知业务模块的门禁。

兼容内容包不执行宿主安装/启动代码，并不代表其中的自然语言天然可信。项目 Skill 驱动的后续基础工具调用仍受原有权限、项目范围和审批约束；不承诺用文本分类器证明一份 Skill 没有提示注入。

### 5.2 可选的设计约束资源

仅当插件业务需要结构化视觉约束时使用本节；它是统一资源协议下的一个示例，不要求所有插件实现，也不要求增加风格选择界面。若声明此类资源，必填：ID、显示名、描述、版本、适用平台、token、布局规则、组件规则、动效规则、可访问性约束、适用/不适用场景、示例与资产许可。资源不能包含凭据、工具授权或自动执行要求。

```json
  "motion": {"durationMs": 160, "respectReducedMotion": true},
  "accessibility": {"minTextContrast": 4.5, "visibleKeyboardFocus": true},
  "do": ["保留加载、空、错误和禁用状态"],

```

验证颜色/token 类型、数值边界、对比度目标及引用完整性；对比度目标仍须在实际组件组合中验收，不能仅凭 JSON 字段声称符合。说明文字只补充结构化规则无法表达的意图，不重复整份 Skill。

### 5.3 设计类模块内部的资源应用规则

- 仅当设计模块已有或确需此业务选项时，在模块详情展示有效设计约束；统一插件框架不新增通用风格选择器，不恢复输入框上方一整行模块栏。
- 本条消息未选所属专业模块时，项目保存的设计偏好也不注入。
- 新设计：用户本轮明确要求 > 本轮选定风格 > 项目已固定风格 > 模块默认；在宿主权限与模块业务合同之内应用。有效来源在详情中可查看。
- 已有项目还原：默认沿用真实项目 token 与视觉证据。插件默认不能改变原貌；用户明确要求改风格时转入有范围的改版任务，保留冻结基线。
- 一个目标产物仅有一个基础风格，可叠加声明字段白名单的品牌 token 覆盖；同一字段发生冲突必须可解释，不按插件安装顺序拼接。
- 项目风格保存稳定 ID、版本、hash 与用户覆盖；包更新不能静默改变既有项目。更新风格须显示变化并由用户应用。
- 多模块只影响各自目标产物；需要共同设计同一产物时冻结一个有效风格快照。
- 设计约束随所属插件打包、版本化与卸载；模块在自己的资源声明中引用它，不要求用户额外安装资源。安装插件不会自动选中其专业模块。

### 5.4 按需加载与预算

目录仅加载插件元数据和 Skill 引用；运行时仅解析所选模块，只有已授权且实际需要的 Skill revision 才读正文。安装 100 个插件不会扫描或复制 100 份项目 Skill，也不会把它们放进模型上下文。

V2 初始硬上限：每提示 UTF-8 16 KiB，插件提示合计 64 KiB；每个解析后的 Skill 正文仍遵守项目 Skill 系统的预算；每风格说明 8 KiB，完整风格 JSON 32 KiB，每个对象最多 128 个字段、数组最多 64 项、嵌套深度最多 8。每轮固定提示与风格编译结果合计不超过 64 KiB，计入引用包装等实际发送文本；最终完整模型请求还须符合上下文剩余预算。必需合同超额必须在调用前说明并阻断，不悄悄截断。

V1 原有字符预算继续按原合同解析，不以 V2 字节限制直接否定旧包。预算是客户端初始策略，基准测试和版本记录可调整，不能让插件自行无限提高。

## 6. 独立插件包格式

### 6.1 文件布局与兼容

采用 `.ddplugin` 扩展名的 ZIP 容器，便于本地、离线及私有源复用；这是本草案的推荐格式。可移植包不带安装脚本，不打包 `node_modules`、运行缓存、凭据、绝对路径、用户作品或项目 Skill 正文。

```text
acme.design-kit-1.0.0.ddplugin
  plugin.json
  integrity.json
  signature.json
  README.md
  LICENSE
  THIRD_PARTY_NOTICES.md
  CHANGELOG.md
  prompts/workflow.md
  styles/clean-business.json
  runtime/module.mjs
  surfaces/module/index.html
  assets/icon.png
  assets/clean-business-preview.png
```

统一清单示例：此插件声明一个受信模块 runtime、一个右侧 Surface、一个已有项目 Skill 引用及内部设计约束；不需要这类约束的插件可省略 `styles` 声明和目录。

```json
{

  "publisherId": "acme",
```

示例域名仅说明字段，不是已存在的市场或项目地址；这个示例提供自己的文字工作流，不因模块显示名相似而获得官方原型工具。跨模块工具使用仍须满足对应模块选择、公开能力合同和原有权限。

标准脚手架默认生成一个可运行模块，模块清单不能为空；多个模块必须分别声明工具、Surface、服务和 Skill 引用。Skill 引用必须解析到宿主已知的项目/工作区 Skill，不允许以包内路径提供正文。包内运行资源与所属插件共用安装、启停和版本事务；不为某一种资源建立另一套插件安装协议。

`dependencies` 项为 `{pluginId, versionRange, required}`，来源与发布者由安装器在用户可见的计划中锁定；不能由未信任包指定认证信息或搜索全网最高版本。`exports` 项为 `{resourceId, kind, apiVersion, visibility}`，visibility 为 public 或明确消费者列表；resourceId 必须归本包所有，Skill 只能作为宿主资源引用，不能通过 exports 重新发布或绕过所属模块门禁。解析后形成包含精确版本、摘要和来源的 lock，不在每轮运行重新择优解析。

V1 `plugin.json` 继续只读兼容，显式标记“旧版清单插件”。用户执行转换时产生新的 V2 包和可检查的引用映射；不凭名称吞并工作区用户 Skill，不让旧宿主写回/降级 V2 格式。V2 不兼容当前 parser，必须先发布支持包格式的宿主。

### 6.2 完整性、来源与发布者

- `integrity.json` 使用确定性 UTF-8 编码，记录所有载荷文件的相对路径、字节数、SHA-256，按路径排序；不包含它自身和签名文件，二者是固定保留项。除这两个保留项外未列出的文件一律拒绝。
- `signature.json` 对 integrity 文件的精确字节签名并包含算法和 keyId；manifest 已在载荷清单内，发布者、ID、版本与所有资源受签名约束。首版算法固定 Ed25519，宿主负责将 keyId 绑定受信发布者；包自带公钥不能自证可信。
- 市场索引另记录完整压缩包 SHA-256 和大小，下载后双重校验；同 ID、同版本、不同摘要拒绝，无论来源是否相同。
- 私有源首次导入信任锚由用户查看发布者和指纹后确认；密钥轮换/撤销记录版本化，旧签名链与不可变发布记录保留。
- 本地文件可以附用于数学签名校验的发布者公钥证明；未知作者显示“未验证发布者”，用户可显式信任该插件 ID/密钥绑定后安装内容包。该本地信任不等同官方认证、不自动覆盖整个作者命名空间、不授予 runtime 权限；已有绑定冲突与保留官方身份不能用普通安装确认覆盖。此流程无需市场账号，更新源也不从包自报地址自动启用。
- 未签名包只允许内容配置，通过可见的本地开发模式在隔离测试数据根加载，不显示“已验证”。开发包不能替换生产插件或默认进入自动更新。
- 许可证字段可用 SPDX 或带随包许可正文的 `LicenseRef-*`；素材字体附第三方许可说明。私有分发与可信程度、许可类型分别表达。

### 6.3 解包边界

校验压缩前后实际大小与文件数量，拒绝路径穿越、绝对路径、软/硬链接、Windows 保留路径/ADS、大小写及 Unicode 归一后重名、嵌套压缩执行内容。不能直接调用全量 extractAllTo 后才检查。

初始限额：压缩包 50 MiB、展开后 200 MiB、2,000 个文件、单文件 16 MiB、最大路径长度 240 字符；prompt/Skill 等文本继续应用更小的专用限制。限额在读/解压过程中执行，不仅相信 ZIP header。大模型与大型媒体另经明确的资源下载流程，不塞进插件包。

可调研复用现有 ZIP 库，但必须通过恶意 archive/流量/内存测试后决定，不能因已有依赖就假设安全。现阶段不新增依赖。

## 7. 安装、更新、卸载与数据所有权

### 7.1 存储布局

业务根由现有 locator 解析，不硬编码用户主目录：

```text
<dataRoot>/agent-plugins/
  registry.json
  sources.json
  packages/<pluginId>/<version>/<packageHash>/
  staging/<transactionId>/
  transactions/<transactionId>.json
  leases/<instanceId>/<runId>.json
  data/<pluginId>/
  overrides/<pluginId>/
  resource-objects/<contentHash>/
  cache/<pluginId>/
```

版本包只读且不可变；registry 记录活动版本、启用状态、来源/信任、授权 revision、事务与依赖锁定。用户覆盖每次编辑生成不可变内容对象，overrides 只保存当前 revision 指针；运行/恢复引用的旧对象不能被编辑或 GC。全部业务 JSON 写入复用 `safe-file.ts`，事务日志与 registry 不做原地半覆盖。项目作品继续留在现有项目数据位置。

### 7.2 安装与更新事务

用户流程：发现/选包 → 查看作者、内容、权限、依赖和兼容性 → 确认安装 → 准备包 → 激活 → 显示结果和“添加到消息”入口。包下载进度、校验、配置不足与失败原因分别显示。

事务阶段：`downloaded → verified → staged → prepared → committed → finalized`。

1. 下载/导入在 staging 中完成；取消只清理本事务拥有的文件。预览 token 绑定包摘要、依赖锁和目录 revision，修改后确认失效。
2. 依赖解析遵守固定来源、版本范围与明确导出资源；拒绝依赖环、版本冲突和未知必需能力。可以一起展示安装计划，但不能静默启用专业模块或授予新权限。
3. 更新先展示版本变更、权限增加、兼容性、数据迁移、用户覆盖差异。默认提示更新，由用户应用；不在运行中替换资源。
4. 激活新版本前阻断新任务并排空有关包及依赖的写租约；在插件私有数据的影子副本上迁移。新插件启动的准备/健康检查阶段无真实业务副作用。
5. 用跨进程 writer 锁和 registry revision/CAS 原子切换版本及数据指针。旧运行锁定原包与摘要；无法安全切换的数据变化等待所有旧写者退出。
6. commit 前失败保留原状态；commit 后错误先读回真实 registry 阶段再恢复，不能当成“没提交”盲目重试。每个阶段都可故障注入验证。
7. 纯包回退仅对声明兼容的数据有效。反向不兼容的数据迁移须保留备份并显式解释限制；不得自动恢复旧数据覆盖更新后产生的作品。

### 7.3 多实例一致性

开发版与安装版共享数据根，管理事务必须协调所有实例。复用/扩展已有实例 lease 与原子文件能力；不能用进程内 Map 或单次 PID 探测冒充跨进程锁。

管理 intent 建立后，各参与实例停止新准入、报告持有的版本/数据 lease；完成后发布 registry revision，并在新任务执行前重新核验。租约需带不可复用实例身份与活性证明；仅超时不是强删活跃租约的依据。

旧实例不认识 V2 管理协议时，暂停迁移/激活/卸载/权限撤销/数据清理并提示关闭或升级该实例。停用请求在本实例立即关闭新准入，但只显示“等待旧实例退出”，全部实例确认前不能声称全局已停用；不能让旧实例继续写新 schema。新安装 V2 的校验准备与下载仍可进行。文件系统不满足所需原子/锁语义时明确不支持管理写入，不悄悄降级为不安全操作。

### 7.4 卸载和清理

先按停用合同关闭准入和处理租约，再解除注册。必需依赖被其它已启用插件引用时阻断卸载，并显示依赖列表；不递归连带卸载其它插件。

| 数据 | 默认卸载处理 |
| --- | --- |
| 插件提示、风格、runtime、Surface、代码、图标 | 从能力目录移除；无运行/恢复引用的包可回收 |
| 项目/工作区 Skill | 仍由原 Skill 系统管理；插件卸载不删除、不覆盖、不迁移 |
| 用户作品、项目原型、媒体、会话 | 保留，由宿主通用查看/导出能力访问 |
| 用户设置、提示/风格覆盖 | 保留，重新安装可恢复；清理是单独操作 |
| 包缓存 | 可清理，只删除有明确所有权的路径 |
| 插件专属授权/凭据引用 | 撤销准入；独占凭据删除或留存选项明确告知，不删除共享模型/渠道凭据 |
| 审计与运行证据 | 保留；旧包缺失显示缺失，不伪造恢复成功 |

有可恢复运行引用时，卸载页说明保留所需版本还是放弃恢复；不能静默删除仍被引用的唯一包。日常 GC 默认保留当前和上一可用版本，额外版本仅在无租约、无恢复引用时回收；缓存容量可设置。

## 8. Host SDK、权限与运行快照

### 8.1 公开接口边界

建议新增可独立发行的 `packages/plugin-sdk`，作为 Schema、纯类型、解析/归一化与兼容校验的唯一事实源；shared 只适配/重导出，不保留另一份权威解析。SDK 不依赖 Electron 或未发布的宿主 shared；作者工具 plugin-kit 与宿主分别依赖 SDK。插件不能 import 宿主内部路径、其它插件源码、`ipcMain` 或 renderer 全局状态。

| SDK 合同 | 入参/返回与所有权要求 |
| --- | --- |
| 工具贡献 | 注册 schema、读写/副作用分类、取消能力、幂等声明；调用携带可信 plugin/module/run 身份，返回结构化结果/错误 |
| 界面贡献 | 注册 surface 描述和入口；通过 host bridge 请求导航/授权资源；由宿主决定会话侧栏/独立页面，不直接改全局导航 |
| 资源访问 | 用包资源 ID 或宿主签发句柄，不接受任意磁盘根；私有写目录由宿主分配 |
| 事件 | 按 run/session/project 作用域发布，订阅返回幂等释放句柄，禁止全局无限广播 |
| 生命周期 | register/prepare/start/stop/dispose 明确谁创建、谁释放；启动健康与供应商配置健康分别报告 |
| 取消与超时 | 所有长任务接收取消信号和截止时间，回执绑定 requestId；迟到结果不改变其它任务 |
| 产物 | 声明 MIME/schema、创建者、版本和导出表示；宿主保存通用只读回退 |
| 数据迁移 | 仅迁移插件私有数据，声明 from/to schema、兼容性、失败恢复方式；不可修改别的插件/用户项目文件 |

宿主提供共享媒体等明确能力接口；影像插件依赖媒体能力不等于选择画布模块。浏览器/终端仍是公共基础能力，不能被某个插件的关闭操作一并停掉。

通用业务错误至少区分：未安装、已停用、缺依赖、不兼容、未选择、权限不足、版本已变化、正在被其它实例使用、事务待恢复、资源超额、数据迁移失败。中文提示提供可行动下一步，日志保存稳定错误码及脱敏上下文。

SDK 类型之外必须实现真实 Host：受信入口加载、进程 runner、带版本的 RPC、能力 broker、动态工具代理与撤销、surface 承载。可信包增加 `runtime: {entry, format, protocolVersion}` 和可选 `surfaces: [{id, entry, apiVersion}]`；entry 都是完整性清单内的相对文件，不能是 URL 或命令字符串。首版 runtime 为自包含 ESM bundle，不接受任意外部 npm 安装或原生二进制；UI 为静态本地 bundle。平台无法满足时预览明确阻断。

RPC 调用者身份由宿主连接绑定，不能信任消息自报 pluginId；每次调用核对 run/作用域/权限与版本租约。先用一个无真实业务的 echo/tool/surface 包证明同一宿主二进制可动态装卸，再开始业务迁出。

### 8.2 可信业务插件与后续第三方执行

官方 runtime 的独立进程用于故障隔离，所有已迁出能力通过 broker 合同使用。代码规范/静态导入检查不足以阻止恶意 Node 代码；此阶段不声称具备对任意插件的安全隔离。

插件界面使用受限 surface bridge，不给完整 preload；内容安全策略、导航、弹窗、下载、剪贴板及网络均有独立授权。模块 UI 不得获得未授权项目或任意文件 URL。非可信运行时开放前必须证明直接绕过 SDK 也无法访问未授权资源。

资源限额以宿主可执行的 deadline、并发数、取消和进程退出为基础；内存/CPU 监测阈值与平台真实强制能力分开表述。日志和诊断不能包括密钥、完整用户提示、私有源认证 URL。长任务实际模型/外部服务费用仍由现有授权流程决定。

### 8.3 运行与恢复记录

每轮冻结：插件 ID/版本/包 hash、依赖锁、模块选择、解析后的 Skill 作用域/版本/hash、提示 hash、风格及覆盖内容对象 revision/hash、权限 revision、数据 schema、Host API。Skill 正文仍由项目/工作区 Skill 系统保存，插件只锁定解析结果；用户修改 Skill 后新运行使用新 revision，旧运行/恢复仍可加载所引用旧对象；只有 hash 没有内容不算可恢复快照。运行中更新不能改变它们。

审计分开记录选择、解析、注入、实际加载和工具执行。不能因为包声明了工具就显示已调用，不能按工具名猜模块归属。恢复必须核验同一快照和既有 Journal/Pi 事实源；原包缺失、权限被撤销或数据不兼容时解释阻断，不换新版继续旧任务。

Automation 配置可显式保存模块选择作为后续任务授权；每次触发仍检查全局开关与当前权限。普通消息的选择不自动升级为永久授权。内部 Canvas/运维任务保留宿主签发的受限能力，不让插件清单伪造内部授权。

## 9. 设置中的插件中心与市场

设置一级入口“插件”，内部四个页面：

| 页面 | 必须包含 |
| --- | --- |
| 市场 | 搜索/分类、官方/社区/团队来源筛选、兼容性、详情、安装/更新、离线状态 |
| 已安装 | 启用开关、状态/版本、更新、配置、Skills/风格、权限、卸载、诊断 |
| 插件源 | 官方、社区、私有源列表，登录/信任状态、刷新、停用/移除源 |
| 开发者 | 隔离开发根、加载本地包、校验报告、模板入口、开发日志、打包/诊断导出 |

详情需展示：作者、版本、来源、许可证、适用平台、实际能力列表、所需权限、依赖、离线能力、外部服务和可能费用、截图、变更记录、支持链接。必需外部服务未配置时显示待配置，不伪装成启动故障。

插件配置使用声明式 `settingsSchema`：字段仅接受 boolean、有限整数、普通文本、枚举和 credentialRef，声明 key、中文 label/description、默认值、范围、是否必填及生效时机（下一任务/重启插件）。不允许 HTML/脚本校验器或读取任意环境变量。敏感值通过宿主凭据 UI 保存，不进入模型提示、普通设置 JSON 或诊断导出；普通配置修改也要版本化，使当前运行沿用原配置快照。模型/渠道优先引用现有配置身份，避免每个插件复制一套凭据管理。

Skills 页保留资源浏览、所属标签和到插件详情的跳转；原 ModuleCatalog 不再保留另一套安装管理状态。聊天菜单只展示已启用且可选的专业模块，底部提供“管理插件”跳转；关闭模块的失效草稿仍保留可见原因。

首版市场是可验证的目录与安装体验，不引入支付、评分、排行榜或社交账号系统。无官方服务地址时不编造在线内容，使用真实源配置和本地夹具验收；目录上线与包发布是单独的发布动作。

## 10. 官方、社区和私有分发协议

- 包格式与分发渠道分离。同一已签名包可本地导入、离线安装、从团队源或公共源下载，不依赖唯一云服务。
- 首版源采用 HTTPS JSON 索引和静态包下载即可；私有源在此基础上增加身份验证。源必须声明 ID、索引版本、生成/过期时间、单调 revision、发布者信任、各版本的摘要/大小/兼容/撤回信息。
- 宿主固定安装来源和发布者身份，不能从公共源拉到“更高版本”便替换同名私有包；换源需要可见操作及身份校验。重复 ID 不能根据网络返回顺序覆盖。
- 私有认证只存现有安全凭据设施，索引/包/诊断导出只保存 credentialRef。跨域跳转不携带原认证；下载目标与重定向遵守源声明的范围。
- 撤回版本停止新安装，保留历史元数据；明确安全撤销可以阻断运行并显示原因，不抹除用户作品。源故障或登录过期不等同撤销，已安装的本地有效包仍可使用。
- 离线显示已缓存目录及同步时间，不能声称已是最新。新安装仍需满足本地可验证的签名/摘要/信任有效性；不能借离线跳过校验。
- 源刷新仅下载元数据，不执行插件、不上传会话或作品；一次只刷新用户配置的源。允许配置后台更新检查，默认仅启动时/手动检查，不在每次输入时访问市场。
- 索引初始上限 5 MiB、单页 100 项，支持分页/ETag；图标截图按可视区域惰性加载，登录失败和网络失败分别显示。
- 移除源不自动卸载现有插件；显示更新已暂停。导出安装清单包含 ID、版本、摘要与来源标识，不含访问令牌或私有下载签名参数。

## 11. 让其他开发者能参与的规范

### 11.1 必须先交付的作者工具

提供一个标准插件脚手架，统一清单、模块入口、Skill 引用、提示、工具、Surface、受控服务、状态、设置、测试与文档。公开版本化 JSON Schema、Host SDK、错误码、能力/平台支持矩阵、BDD 契约测试和本地调试说明；脚手架不得生成或打包 Skill 正文，不同业务示例均从同一脚手架生成。

首版生成可安装的模块 runtime 合同和 Skill 引用样例；内容型旧包仅作为兼容验证，不作为新业务插件目标。脚手架升级给出迁移说明，不覆盖作者业务文件。SDK 与 plugin-kit 产出独立发行物，名称建议为 `@dutydeck/plugin-sdk` / `@dutydeck/plugin-kit`，发布前核验可用性；不得残留 workspace 依赖、monorepo 绝对路径或宿主源码导入。下面的仓库 scripts 只是公开 CLI 的转发入口，外部作者可在自己的仓库直接使用相同能力。

规划的统一命令（当前尚不存在）：

```bash
bun run plugin:validate ./examples/plugins/design-kit
bun run plugin:pack ./examples/plugins/design-kit --out /private/tmp/design-kit.ddplugin
bun run plugin:verify /private/tmp/design-kit.ddplugin --development
bun run plugin:test ./examples/plugins/design-kit
```

`validate` 校验清单、所有引用、归属、命名、预算和材料完整性；`pack` 按白名单生成确定性包，不执行作者安装脚本；`verify` 复用宿主的解包/摘要/信任校验；`test` 运行模板契约夹具。示例流程没有 signer，产生未签名内容包；`verify --development` 只在内容/完整性通过时退出 0 并明确输出“仅开发可用”，不能将结果当成生产可安装。

正式发布时 `pack --release` 从已配置的安全 signer 句柄生成 signature.json，缺 signer 即失败；密钥值不在 CLI 参数/日志出现。CLI 的 publisher init 提供生成/导入作者密钥与导出公钥/指纹的流程，独立 `--config-dir` 管理 signer 与信任，不能依赖 Electron 安装或宿主业务根。不带 `--development` 的 verify 使用该独立配置的信任库；缺签名、身份不符或未建立信任均非零退出。桌面安装器使用其自身数据根的信任库，首次未知作者可按上述明确流程建立信任。测试可注入隔离的固定测试密钥/信任库；不修改用户信任。确定性要求覆盖 ZIP entry 顺序、时间戳、权限位、压缩参数、integrity 与 signature 编码。

开发加载只在隔离测试数据根进行，有明确“开发中”标识；不能通过加载本地目录覆盖正式安装版本。正式包始终不可变，调试热重载只针对开发实例。

### 11.2 贡献与兼容规则

- 包必须有维护者、支持入口、许可证、第三方素材说明、变更记录、支持矩阵和最小测试。只声明实际测试的平台，不把 CI 未跑平台标成支持。
- 包使用 SemVer；工具输入输出破坏、数据不可兼容或主要工作流变更提高 major；兼容能力增加提高 minor；修复提高 patch。默认 Skill 正文改动仍递增 Skill 自身版本。
- Host API 的破坏变化提高 major；同一 API major 内只增加兼容字段/能力，未知可选字段可保留，未知必需能力明确拒绝。弃用至少提供两个宿主 minor 版本的适配窗口，安全问题可提前停止并解释。
- 官方、社区、私有包共用技术校验；发布/审核权限可以不同。社区作者不需要修改 orchestrator、主 IPC 巨文件或全局工具白名单才能提交包，但只有宿主 allowlist 的 runtime 才能获得执行能力。
- 业务插件通过公开 SDK 注册，禁止跨插件内部 import。共享工具由单独维护者拥有，消费者走明确版本接口。
- PR 模板包含用户变化、权限差异、数据迁移/回退、性能证据、兼容范围和验证日志；评审不能仅以“已编译”代替安装/运行/卸载。
- 安装行为、SDK 合同与发布包必须同一版本验收；CI 不使用真实付费模型或用户数据，真实供应商验收单独安排。

## 12. 验收矩阵与性能边界

| 场景 | 必须观察到的结果 |
| --- | --- |
| 安装两个同名 Skill/模块 | 稳定身份不冲突，显示所属，短别名歧义可解释 |
| 插件已启用但消息未选模块 | 无对应 prompt、Skill 正文或专业工具注册 |
| 关闭插件后用旧 chip、手写 Skill、队列、Automation、内部委派 | 同一门禁生效，无后台重新激活 |
| 安装/更新各阶段取消、断网、磁盘满、崩溃 | 已有可用版本不遭半覆盖，事务可核验恢复 |
| Dev 和安装版并发安装/更新/停用 | registry 单一事实源，租约和 revision 无丢失更新 |
| 内容被改、签名不符、路径逃逸、解压超额 | 进入活动目录前阻断，并提供字段/文件级错误 |
| 同版本不同摘要/不同发布者/换源 | 拒绝自动替换 |
| 包/依赖/权限/风格变化后的旧运行恢复 | 锁定原快照或说明阻断，不静默混用 |
| 卸载后重装 | 用户作品与覆盖仍在，共享 Skill/凭据不受误删 |
| 设计还原和明确改风格 | 前者保留项目视觉证据，后者按目标范围应用并记录风格来源 |
| 单插件崩溃、超时、取消迟到 | 其它模块可用，不错误提交迟到结果 |
| 市场离线、私有源过期、没有搜索结果 | 三种不同状态；本地已安装能力仍可管理 |
| 深浅主题、窄窗口、键盘/读屏 | 开关、安装、详情、失效 chip 均能操作并反馈焦点 |
| 新贡献者制作插件 | 只依标准脚手架与 SDK 即可校验、安装、选择并运行所支持能力，不修改宿主业务 |
| 作者工具独立发行 | 仓库外只安装发行物即可制作包含自身模块及资源的插件，无 workspace 或宿主源码依赖 |
| 内容包直接分享 | 独立作者签名，本地文件可建立限定信任并安装，无市场上架前置 |
| 包内资源完整性与所属关系 | 不含设计约束的插件也有效；声明了缺失资源则报错，未选所属模块不注入，停用后不重新加载 |

最小回归含模块门禁、共享媒体、内部受限任务、消息队列、Journal/Pi 恢复、WorkContext 导航以及四层 IPC。全仓历史失败要归因，不能把定向通过称为全仓通过。

初始性能验收目标（需在标注设备与样本上测量，不是当前实测）：100 个内容插件元数据热缓存解析 P95 ≤ 50 ms；未选专业模块的每轮资源正文读取次数为 0；关闭并收束后该插件活动服务/订阅/计时器为 0；50 MiB 包解包增量 RSS 目标 ≤ 256 MiB；市场搜索使用已缓存索引且不阻塞输入。目标未达先定位，不为凑数字静默丢资源。

## 13. 分阶段完成标准

1. **统一规范、脚手架与模块接入**：身份/模块/Skill 引用 schema、独立 SDK/CLI；作者用同一脚手架开发包含 runtime、工具、Surface、提示与按需资源的真实安装包。
2. **生命周期与管理**：启用/停用、升级/回退、数据所有权、跨实例事务、资源快照和设置插件中心完整闭环。
3. **市场与私有源、外部作者验收**：共用安装器/信任协议，独立仓库基于标准脚手架开发插件、签名和直接分享；在同一候选发布版验证，再从正式发行入口复验。此阶段不等待业务模块迁出。
4. **运行宿主与交互设计试点**：真实 runtime/broker/surface 验证后迁出服务、工具、界面；原型作品与历史兼容，旧硬编码装配退出生产路径。
5. **业务生态扩展**：其余专业模块按依赖顺序迁移；第三方可执行插件定义公开准入路径，真实隔离验收后再开放，不永久限定官方作者。

只有当业务代码、工具、UI、服务、状态与数据适配能随独立包交付，且不修改宿主核心也能安装/更新/卸载时，才称该模块“完整插件化”。Skill 仍由项目/工作区系统提供；首版应如实称“统一插件机制已支持模块 runtime、Skill 引用、提示与受控 Surface”，并列明尚未开放的第三方执行能力。
