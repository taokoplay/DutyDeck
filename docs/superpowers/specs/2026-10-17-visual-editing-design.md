# 影像创作剪辑成片设计

## 1. 目标与边界

影像创作已经具备作品、集数、资产、分镜、采用媒体和 Agent 制作任务，但还不能把已采用镜头组织成可反复修改的成片。剪辑成片页解决三个连续问题：

1. 按集把分镜组织成一条可预演的主时间线。
2. 允许用户调整顺序、分割、裁切、字幕和音量，同时保留源镜头和源媒体不变。
3. 让主 Agent 读取当前剪辑并提出可检查、可撤销的修改方案，最后导出真实视频任务。

剪辑成片是影像创作中的新增页签，不改动画布、分镜和原有作品编辑流程。素材导出继续负责下载已采用媒体和制作清单，导出成片负责合成时间线后的 MP4，两者使用不同入口和不同任务状态。

首版包含顺序粗剪、片段排序、分割、入点/出点裁切、旁白与音乐音量、字幕、Agent 修改方案预览与采用、真实 MP4 导出。复杂特效、关键帧、调色、多人实时协作和云端渲染不进入首版。

## 2. 用户体验

### 2.1 入口与布局

在 `VisualProductionWorkspace` 增加“剪辑成片”页签。影像工作台处于窄侧栏时显示紧凑预览和时间线摘要，用户点击“展开精剪”后进入完整编辑布局；主 Agent 仍使用 DutyDeck 旁边已有的对话面板，剪辑页只提供当前集、当前片段和当前时间线作为对话上下文，不复制聊天输入框。

完整布局沿用原始剪辑参考包的职责分区，但适配 DutyDeck 的主题和组件：顶部集数与保存状态，中部播放器，底部横向时间线，右侧检查器按需打开，左侧素材栏按需展开。播放器点击播放时按照视频轨片段的时间顺序播放；静帧、视频、声音缺失时显示明确占位和原因。

### 2.2 集数与时间线

每个集数有且只有一条主剪辑时间线。首次进入没有时间线时，页面提供“按分镜创建剪辑”，按当前分镜顺序引用已采用输出；没有采用输出的镜头不自动加入，并显示缺口。空集不创建虚假的片段。

集数切换只切换时间线和播放器上下文，不改变作品正式版本。切换期间未保存草稿必须先完成保存或明确显示冲突，不能静默丢弃输入。

### 2.3 编辑操作

- 拖动片段调整顺序，片段拥有稳定身份，排序变化不修改 `VisualShot` 的顺序。
- 分割只生成两个新的时间线片段，两个片段继续引用同一个源媒体和不同的入点/出点。
- 裁切只改变时间线片段的入点/出点，不覆盖源媒体。
- 旁白、音乐和字幕在独立轨道展示；音量和字幕修改只作用于时间线。
- 片段检查器通过项目默认 Dialog、Input、Select、Textarea 等组件打开，保存按钮固定在弹窗底部，窄窗口下内容区域独立滚动。
- 撤销/重做作用于当前编辑会话的命令栈。成功保存后仍可撤销本次会话操作；重新打开后只恢复已保存状态，不伪造跨会话撤销历史。

## 3. 领域模型

剪辑模型与 `VisualProductionDocument` 分开保存。作品正式版本描述“拍什么”，时间线版本描述“怎么剪”，避免剪辑微调导致镜头候选、资产和 Agent 作品版本失效。

```ts
interface VisualEditingDocument {
  schemaVersion: 1
  id: string
  productionId: string
  episodeId: string
  revision: number
  baseProductionRevision: number
  tracks: VisualEditingTrack[]
  duration: number
  createdAt: number
  updatedAt: number
}

interface VisualEditingTrack {
  id: string
  kind: 'video' | 'voice' | 'music' | 'caption'
  clips: VisualEditingClip[]
}

interface VisualEditingClip {
  id: string
  source: {
    type: 'shot-media'
    shotId: string
    mediaId: string
    mediaHash: string
    shotOutputVersion: number
  }
  start: number
  duration: number
  sourceIn: number
  sourceOut: number
  label: string
  volume?: number
  caption?: { text: string; start: number; duration: number }
}
```

实际类型需要遵循项目现有 `interface` 与校验器风格，不能把媒体字节、本机路径、远端 URL 或凭据放进时间线。`mediaHash` 和 `shotOutputVersion` 是判断源媒体是否变化的依据；`sourceIn`、`sourceOut` 和 `start` 使用非负秒数，保存前必须校验轨道不越界、片段不重叠（首版视频轨只允许顺序拼接）以及字幕时间落在时间线范围内。

时间线快照包含当前正式时间线、可选 Agent 候选、导出任务摘要和关联的作品/集数身份，但不携带媒体二进制。媒体预览继续复用现有媒体内容读取能力，并按当前选中片段懒加载。

## 4. 版本、联动与失效规则

1. 建立粗剪时读取当前作品和集数的正式快照，只引用当时已采用的媒体。
2. 镜头产生新采用版本后，旧时间线仍保持原 `mediaId`、`mediaHash` 和 `shotOutputVersion`，片段标记为“源镜头有新版本，可替换”。系统不自动替换，避免用户已经做好的节奏被破坏。
3. 资产或镜头设定变化只影响后续生成和“需要更新”提示，不直接重写时间线。
4. 作品删除集数或镜头时，保存时间线必须阻止悬空引用并给出迁移提示；历史时间线不因为后台刷新自动消失。
5. 时间线 revision 与作品 revision 独立递增。保存时间线携带 `expectedRevision`，主进程发现版本变化时返回冲突，保留本地草稿并提供重新读取、覆盖前先查看差异的路径。
6. Agent 候选绑定 `productionId`、`episodeId`、`timelineRevision` 和创建会话。候选过期时只能查看差异，不能直接采用。

## 5. Agent 变更合同

Agent 继续通过旁边的主对话工作。宿主向 Agent 提供有界的时间线摘要：集数、总时长、视频片段顺序、来源镜头/版本、音频轨和字幕摘要，不发送媒体字节。

Agent 只能提交结构化编辑方案，不能直接覆盖时间线。首版操作集合为：

- `moveClip`：移动片段顺序。
- `splitClip`：在播放头分割片段。
- `trimClip`：修改入点/出点。
- `setVolume`：修改旁白或音乐音量。
- `setCaption`：新增、修改或删除字幕。
- `removeClip`：删除片段并留下缺口说明。

宿主按 `timelineRevision`、片段身份、源媒体 hash 和集数身份校验方案，生成候选时间线和影响摘要。候选在“采用”前只用于预览；采用后以一次原子保存递增时间线 revision，并把操作写入可撤销命令栈。任何跨集数、修改源媒体、修改作品资产或绕过媒体授权的操作都直接拒绝。Agent 的重试提示引用最新时间线和最新镜头版本，不复活旧任务，也不自动发送消息。

## 6. 持久化与 IPC

沿用影像制作现有主进程存储根、`safe-file.ts` 原子写入、sessionId/productionId 校验和 renderer → preload → main 四层 IPC 契约。新增接口集中在剪辑命名空间，建议包括：

- `loadTimeline`：读取某作品某集的时间线快照；没有时间线返回空状态。
- `saveTimeline`：带 `expectedRevision` 保存已校验时间线。
- `createRoughCut`：按当前分镜和采用媒体创建初始时间线。
- `proposeTimelineEdit`：登记 Agent 候选，不直接修改正式时间线。
- `adoptTimelineEdit`：校验并原子采用候选。
- `discardTimelineEdit`：结束候选，不回写正式时间线。
- `requestExport`：冻结时间线 revision、片段源媒体 hash 和导出设置，创建导出任务。
- `listExportJobs` / `cancelExport`：读取和取消当前作品的成片导出任务。

主进程必须重新验证所有身份、版本、范围和媒体 hash。renderer 不得传本机路径作为导出输入；导出器只能读取主进程根据作品身份解析的媒体副本。时间线和导出任务都要通过变更事件刷新当前作品，但页面打开不启动服务器扫描或轮询。

## 7. 导出任务

导出任务是独立于 Agent 媒体生成的任务类型，状态至少包括 `queued`、`preparing`、`rendering`、`completed`、`failed`、`cancelled`。任务冻结：

- `productionId`、`episodeId`；
- `timelineRevision`；
- 时间线内容摘要及每个源媒体的 hash；
- 输出比例、帧率、音频和字幕设置；
- 导出器版本和实际输出文件 hash（完成后）。

同一时间线 revision 的重复请求应幂等返回已有任务或明确创建新的用户请求，不能重复隐式消费远端生成。取消只承诺停止本机排队或编码流程，已提交的外部媒体任务不声称可撤回。没有可用本地编码器时任务必须失败并显示能力缺口，不能生成假 MP4 或把素材清单当成成片。

首个编码器实现应接入仓库已有的媒体执行边界；若当前发行包没有可复用的 ffmpeg/编码器定位能力，先补充独立 adapter 和失败态，再决定是否随应用分发二进制，不在剪辑 UI 中偷偷新增依赖。

## 8. 错误、并发与性能

- 作品、集数、时间线、候选和任务全部按 sessionId 与 productionId 隔离；切换作品或集数后，迟到的读取和媒体预览不得写回当前页面。
- 保存冲突保留用户草稿，显示冲突来源和两个 revision 的差异摘要；不自动覆盖他人/Agent 的新版本。
- 缺少媒体、媒体 hash 不匹配、镜头已删除、片段越界、导出器缺失分别使用可行动的错误信息，不能统一显示“操作失败”。
- 播放器只读取当前片段或当前预览所需的媒体，时间线首屏只加载元数据；不把整条成片合成为大数组，也不因滚动时间线重复请求媒体。
- 预览和导出共享已验证的媒体副本，导出前再次校验 hash。导出编码属于高 CPU/磁盘操作，任务状态必须可见，并限制同一作品并发导出数量。

## 9. 验证计划

### 共享类型与主进程

- 合法粗剪、排序、分割、裁切、音量、字幕和空集边界。
- 片段越界、重叠、悬空镜头、媒体 hash 变化、旧作品 revision、跨 session/作品/集数访问均拒绝。
- 时间线保存的 expected revision 冲突保留本地草稿；Agent 候选过期不可采用。
- 导出任务冻结输入，重复请求、取消、编码器缺失、输出 hash 校验和失败恢复可验证。

### renderer 与真实 Electron

- 默认窄侧栏预览、展开精剪、集数切换、空集粗剪、横向时间线、键盘选择和弹窗保存。
- 拖动排序、分割、裁切、字幕、音量、撤销/重做和 Agent 候选预览/采用/撤销。
- 镜头新版本提示但不自动替换；资产、项目、分镜、画布、素材导出页签仍可正常联动。
- 深浅主题、460px 窄窗口、焦点恢复、加载态、空态、失败重试和迟到响应隔离。

验证顺序为相关 BDD 测试 → 影像 renderer/preload/main 类型检查 → 全仓 `bun run typecheck` → 独立 Electron UI smoke。真实 MP4 编码需要在具备编码器的环境做一次输出 hash 和播放器可读性验收；没有该环境时只能报告导出链路未完成，不能宣称成片导出已验证。

## 10. 分阶段实施

1. 新增共享时间线类型、校验器、快照和 IPC 输入/输出；补齐主进程原子存储及冲突测试。
2. 在影像工作台接入剪辑页签，实现粗剪、播放器、时间线和片段检查器；先用已存媒体完成本地预演。
3. 接入 Agent 时间线摘要、结构化候选、差异预览、采用/丢弃和撤销。
4. 接入导出任务与已有媒体执行边界，完成真实 MP4 编码、失败和取消语义。
5. 做完整 Electron smoke、窄屏/主题回归和性能检查，再决定是否扩展特效、关键帧或更多轨道。
