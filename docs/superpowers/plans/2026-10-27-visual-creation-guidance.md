# 影像创作与评审指引优化计划

**目标：** 将用户创作要求转成可核对、可制作的故事与分镜，并消除运行提示中的冲突。

**设计：** 沿用已有作品、集级剧本、资产、镜头字段。完整创作规则在共享包维护并由模块提示注入，脚本页仅携带本轮任务清单以避免重复；执行规则从 orchestrator 提取为单一合同；动态工具提示只陈述本轮能力。质量检查保留证据、授权和版本边界。

**技术栈：** Bun、TypeScript、Pi Agent、现有 Electron 主进程与 React 脚本页。

用户已在本会话评估结论后要求优化，直接执行。保持当前工作区其他未提交改动，不提交、不发布、不进行收费生成。

## 验收与边界

- 需求按“需求→字段→镜头→验收”核对；硬约束冲突应说明选择，不能静默改镜头数、时长、画幅或风格。
- 故事既定规则、角色知情范围、伏笔和回收位置复用现有 productionNotes/资产描述；简介保持精简。
- 台词、动作、停顿与镜头时长可核算；模型生成时长与最终剪辑时长分别说明。
- 审核逐项给出依据、问题和最小修改；主观喜好、结构检查和真实观影/听验分开。
- 锁定资产、外传/付费、CAS、审片证据与真实导出边界保持有效。
- 回归证明模型能够收到一致指令，不声称已证明模型创作质量提高。
