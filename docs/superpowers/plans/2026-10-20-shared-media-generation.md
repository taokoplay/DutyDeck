# 各模块共用媒体生成配置与执行服务方案

日期：2026-10-20。状态：本地实现与离线验证完成，尚未提交或发布。

## 用户目标与范围

用户强调的是 Agent 对话、画布、影像等调用方，统一调用「媒体生成」模块内配置的图片、音频和视频模型。普通 Agent 对话不应要求先选影像插件或写脚本读取凭据。用户已选择：没有项目的对话先选择项目，继续复用现有资产体系。

本方案取代本轮先前围绕通用插件能力声明的实施草稿。插件包协议、第三方可执行 runtime 和能力依赖清单不作为此次接入前提。

## 现有实现依据

- `ipc.ts` 创建 `UnifiedMediaModelCatalog`，直接读取 `getImageGenerationStore().readPublic()` 和 `getAudioGenerationStore().readPublic()`，并由 Store 解析单条凭据。旧 `channels.json` 与历史 `image-generation-models.json` 不应成为新调用方自行读取的配置源。
- `UnifiedMediaModelCatalog` 已提供图片、音频、视频的稳定引用、任务能力和可执行状态。
- `UnifiedMediaGenerationService` 已有准备、执行、查询、等待和取消流程；Agent 工具已定义 `media_list_models`、`media_prepare_generation`、`media_execute_generation`、`media_get_generation`、`media_wait_generation` 和 `media_cancel_generation`。
- 普通 Agent 的媒体装配目前仍依赖画布运行准备，并要求显式媒体模型或画布/影像模块选择。
- 统一生成任务目前存在进程内 Map；不能据现有查询接口宣称客户端重启后仍能恢复远端生成。
- 执行适配目前包括 OpenAI Images、MiniMax 图片/语音/视频、小米语音和即梦图片；配置项不自动等于已支持协议。ComfyUI 继续保留工作流输入合同。

## 规范架构

### 1. 媒体生成配置是唯一模型目录来源

媒体配置模块负责供应商、模型、启用状态、凭据与默认参数；统一目录按类别和任务能力投影安全字段。所有调用方使用同一稳定 `modelRef`，不按显示名重新匹配渠道，不复制或自行读取配置文件。旧历史配置只经明确兼容适配处理，不擅自合并或改写。

公开目录至少区分：已配置、可执行、停用、缺少凭据、未实现适配器及读取失败。目录读取失败不能伪装成空目录。参数说明需提供真实支持的尺寸、音色、时长、参考图数量等约束，禁止接受后静默忽略。

### 2. 所有调用方共用一个执行服务

Agent 工具、Renderer IPC、画布和影像业务服务是薄接入层，调用同一媒体服务，不复制 HTTP 或供应商轮询实现。项目、发起会话、调用模块及目标由宿主签发，Agent 只提交模型引用、提示词与经过授权的素材引用和参数。

媒体服务内部解析凭据并调用协议适配器；密钥不进入工具参数、模型上下文、任务持久化或插件包。取消能力按供应商事实报告，停止本地等待不能被描述为远端任务已经取消。

### 3. Agent 对话直接可用

拥有项目归属的普通用户对话和用户探索分支直接装配精简媒体工具；无需先选专业模块。基础顺序为列模型、检查能力、准备任务、按既有授权执行、等待或查询、展示结果。用户显式选择模型时严格沿用，不先尝试无关工作流或暗中改供应商。

模型选择优先级：本次明确指定 → 当前模块已保存的模型绑定 → 用户配置的对应媒体类别默认模型 → 唯一满足要求的可执行模型。仍存在多个候选时请求选择，不能默认取目录第一项。没有对应默认配置时，不虚构已存在的默认能力。

未绑定项目时给出选择项目的明确诊断；内部审图、委派、自动化等保持各自授权，不能因普通入口开放而继承权限。计划模式可以发现、校验与准备，不能执行收费请求。

### 4. 同一任务与资产，不同模块各自呈现

统一服务返回任务 ID、状态、模型身份、错误分类和媒体资产引用。Agent 对话展示图片或音视频播放器；画布接入目标节点并沿用候选/采纳流程；影像模块绑定作品任务和镜头；其它模块通过其宿主入口消费同一引用。

项目媒体库保存生成资产，保留模型、参数、来源和任务关联。业务模块只保存自己的绑定关系；确需独立副本的既有作品合同继续保留，不在此次强制迁移。

### 5. 异步与错误合同

准备不发生成请求；执行生成稳定任务；轮询、等待、重连都查询原任务。准备与执行之间复核模型/配置身份，执行阶段解析当前有效凭据。任务以 JSON/JSONL 和原子写封装保存非敏感状态、供应商任务标识与输出引用；重启后恢复能够恢复的任务，提交结果未知时明确标记未知，禁止自动重复收费提交。

错误至少区分：项目未绑定、服务不可用、模型不可执行、参数不支持、鉴权失败、额度不足、远端失败及结果未知。脱敏后保留可操作原因，不能一律变成未知错误，更不能据工具缺失推断密钥失效。

## 实施顺序与验收

1. 固定目录和参数合同，核对媒体设置、Agent、画布、影像看到相同配置身份；不为任何模块维护新的模型副本。
2. 从画布接入中抽出共享媒体入口，打通普通 Agent 的图片、语音、视频完整闭环；每类选已实现的协议做隔离集成验证。
3. 接齐各模块调用来源与结果呈现，保留现有画布和影像采纳合同。
4. 完善持久任务恢复、明确错误分类和不重复提交保证；对不支持恢复的协议明确标注限制。
5. 回归权限、跨项目、渠道停用、参数边界、超时、取消、客户端重启；使用隔离 Provider 验证无凭据泄露及无重复收费提交，再运行类型检查和构建。

## 影响与资源开销

不新增依赖或独立网络服务。复用现有目录、适配器和项目资产库，配置只在需要时读取，公开目录可按配置 revision 缓存失效；工具装配不解密全部凭据、不提前访问供应商。普通对话保持精简工具集，大型媒体字节不进入模型历史，状态等待由宿主合并管理。其它模块的专有工具、作品持久化与审批不因媒体共享而扩权。

## 当前进度

- 已从 Canvas 装配中提取共享媒体工具入口，普通项目用户会话和探索分支直接获得统一生成与素材工具；Canvas 与影像保留专业工具。无项目及服务未就绪均提供明确诊断，内部/自动化/委派会话不因此扩权。
- 统一目录公开真实参数；未知参数明确拒绝。默认媒体与画布 Skills 已同步修正模型优先级与工作流选择规则并递增 patch。
- 生成任务采用原子 JSON、操作幂等与提交前版本核验；执行重新解析当前凭据，持久记录不含宿主密钥。MiniMax 视频保存 taskId 后可只续查；无可恢复 taskId 的未知提交保持 unknown，不能自动重发。影像恢复需要重新验证当次可信绑定。
- 对话可按需预览图片、音频和视频；预览由主进程根据消息会话、任务和真实产物签发单文件授权，卸载释放。错误只显示白名单中文原因。
- 已回归会话项目改绑、计划权限、取消、等待、队列与恢复，并修正即梦未知退出被误报为登录失败的问题。
