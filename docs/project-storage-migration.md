# 项目数据目录迁移

DutyDeck 新项目将设计、知识库、交互设计和影像制作数据存放在项目根的 `.dutydeck`。已有项目仍可使用 `.proma`，应用升级不会自动搬动这些数据。

在「设置 → 路径管理」的项目列表点击「迁移项目数据」，核对项目和待迁移模块，再点击「迁移并重启」。迁移前建议备份项目，并关闭其他 DutyDeck / Proma 客户端。应用仍有任务或项目写入时会拒绝迁移，任务结束后可重试；迁移成功后重启以刷新面板和资源路径。

| 原目录 | 迁移后 |
| --- | --- |
| `.proma/design` | `.dutydeck/design` |
| `.proma/knowledge` | `.dutydeck/knowledge` |
| `.proma/interaction-design` | `.dutydeck/interaction-design` |
| `.proma/visual-production` | `.dutydeck/visual-production` |

只移动这四类模块目录，使用同一项目卷内改名，不复制素材正文。未知的 `.proma` 文件与目录、已有的 `.dutydeck/plugin-artifacts` 保留。用户级默认根 `~/.DutyDeck` 以及旧 locator、环境变量、CLI 和恢复临时文件名继续兼容。

同一模块在新旧目录同时存在时，应用会阻止迁移并显示冲突模块。不要直接覆盖或合并目录；先备份，再核对哪份数据需要保留。符号链接、目录身份变化、运行中的任务或其他客户端也会阻止迁移。

迁移中断后，已移动模块继续从新目录读取，其余模块继续使用原目录；路径设置会显示继续迁移入口。恢复记录绑定目录身份，重试会核对已有移动结果，再完成迁移标记。全部目录已移动但最后标记尚未完成时，也能继续恢复。

迁移后旧版本可能无法读取这些项目数据。需要退回旧版本时，先退出所有客户端并从迁移前备份恢复整个项目；不要在仍有任务运行时手工改名。历史会话的已知附件路径在读取时投影到确认迁移后的目录，普通正文、工具命令及原始历史文件不被批量替换。

迁移互斥保护参与该协议的 DutyDeck 实例；Node 的目录改名不承诺抵御其他本地进程在最后一次检查与系统调用之间恶意替换路径。迁移期间请勿通过外部工具同时搬动项目目录。
